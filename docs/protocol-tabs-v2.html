这些字段不是手填的，是后端直接读每个 bin 开头的镜像元数据块解析出来的（型号、版本、CRC32、代码区字节数）。 只比 imgtype=0 的 APP 镜像，boot 镜像不参与 OTA。

五、④ 核对版本（自动）

6逐行比对 纯前端判断
界面：「结论」列 —— 已是最新 / 需升级 v1.82 → v1.83 / 型号不符 / 库里没有
顺序判断结论能不能升
1这块板有没有应答无应答否
2库里有没有这个 id 的固件库里没有这块板的固件否
3设备型号 vs 库型号型号不符（库是 N2SE_M）否
4版本相同 且 CRC 相同已是最新否
5版本不同需升级 v1.82 → v1.83是
6版本相同但 CRC 不同版本相同但 CRC 不同（需重烧）是
为什么版本和 CRC 都要比：版本号是人为标的，改代码忘了改版本号很常见； CRC 是编译产物算出来的，一定跟着内容变。所以版本相同但 CRC 不同 = 内容真的不一样，要重烧。
例子：设备报 v1.83 / 0xDB2742BD，库里也是 v1.83 / 0xDB2742BD → 已是最新，跳过； 设备报 v1.82 / 0x12345678 → 需升级。

八、状态码

码含义能重试吗怎么办
0x00成功—继续下一步
0x10长度 / 容量错误能按 NACK 的 seq 重发
0x11校验失败否停止，重新升级
0x01CRC 错误否检查镜像与校验值
0x02Flash 错误否重来一次，仍失败换板
0x30S 通知队列满否降低发送速率重来
0x31S 通知确认重试耗尽否链路差，靠近设备重来
0x32M 串口未就绪否主控没上电 / 串口不通
0x33M 串口写失败否同上
0x34M 串口帧错误否同上
0x35M 未就绪超时否同上
0x36M 进 Boot 超时否主控没进 boot，重启设备
0x37S 数据静默 5 s否链路中断
0x38M 拒绝数据包否检查包长对齐
0xE1硬件码不匹配否目标选错（M 的帧发给了 S）
0xFF未分类错误否重新进 boot 再升
只有 0x10 能重发。其余码表示设备已经关闭本轮会话，继续重发只会空转。

九、常见失败

点「扫描设备」一直无应答 → 先确认蓝牙还连着；0x24 都超时说明链路断了，不是板的问题。
表格里某块板"无应答" → 点那一行的「重试」单独重读，不用整轮重扫。
握手无应答 → 设备不在 boot，或广播名不对 → 先 0x0610 看模式。
握手被拒 0xE1 → 硬件码发错，M 的帧发给了 S。
参数被拒 → 镜像超过设备容量（S 约 188 KB，M 约 102 KB）。
数据卡住不动 → 包长没 4 字节对齐，或 MTU 太小。
校验老不过 → size 填错 / 固件选错 / 那 32 字节用了真 SHA256 而设备用的是 CRC32+0。
发完成没回应 → 正常，应用期间不消费；断链就重连再发。
复查一直不通过 → 没先断开重连就查询，或者设备还停在 boot。
为什么 boot 不能 OTA：boot 是负责"接收并写入 APP"的那段代码，它把自己覆盖掉就再也起不来了。 现场升级永远只碰 APP 区，boot 只能出厂前用 ST-Link 烧。

待写 按同样格式：界面点哪里 → 读状态 → 三片下发 → 提交 → 轮询 → 比对，每条帧逐字节拆解。

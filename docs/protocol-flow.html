J51NG 协议全流程（场景驱动版）

主线：连接 → 认设备 → 用功能（测距 / 杆包）→ 升级。
全部依据当前固件：主控 M v1.83（0xDB2742BD）· 蓝牙板 S v1.16（0x9AA0FB65）。
字段级细节见 APP_PROTOCOL_SPEC.md；本文只讲"按什么顺序发什么、等什么、错了怎么办"。

文件别名：app_logic.c=S 板 BLE 命令分发、USART.c=S 板 Modbus/杆包服务、golf_recommend.c=M 主控杆包表与推荐、app_ble.c=S 板广播与连接。

0. 怎么读这些图

┌──────┐        方框 = 一步动作（App 侧或设备侧）
│      │
└──┬───┘
   ▼
 ◇──◇           菱形 = 判断（App 侧）
发 / 期          发 = App 发出的帧，期 = App 期望收到的帧
(0xE1)          括号里的码 = 失败分支的 ack
⇒                ⇒ 后面是超时/重试规则

所有帧统一：53 A2 | len(2,LE) | cmd | payload | sum(2,LE)，len = payload+3，sum = 前 5+payload 字节之和。 上行两种帧头都要收：54 A1（主动上报）与 53 A2（命令应答）。

1. 图 0 · 系统总览

   ┌────────────┐   BLE  53A2 / 54A1   ┌───────────────┐   UART EB90 / Modbus RTU   ┌──────────────┐
   │    App     │◄────────────────────►│  S 蓝牙板      │◄──────────────────────────►│   M 主控      │
   │  (手机)     │                      │  N32WB031     │                            │  GD32F303CB  │
   └────────────┘                      └───────┬───────┘                            └──────┬───────┘
                                               │                                           │
                                    杆包暂存区 68 B                            杆包表 68 B / 推荐杆 / 测距
                                    （收到就转给 M）                            Modbus 从站 0x01

   升级通道：App ──EB90──► S(boot) ──EB90──► M(boot)
             ▲ 两条通道帧头不同，别混：日常业务 = 53A2/54A1，升级 = EB90
App 只跟 S 说话。M 没有 BLE，任何"读主控版本/写杆包表"都是 S 代转。
同一时刻只有一条 BLE 链路；连着的时候设备不广播，别人扫不到。

2. 图 1 · 连接与订阅（一次做全，少一步就哑）

① 扫描
   过滤：namePrefix = "AIMTECH"（备用 "J51NG"）
   期望：AIMTECH VHR

② 连接
   Service : 00002760-08c2-11e1-9073-0e8ac72e1001
   Write   : 00002760-08c2-11e1-9073-0e8ac72e0001
   Notify  : 00002760-08c2-11e1-9073-0e8ac72e0002

③ 订阅通知（CCCD 写 01 00）      ◄── 少了这步：所有应答都收不到
④ 请求 MTU 247（单帧 ≤228 B 安全）

⑤ 就绪：可以发第一条命令

写方式：APP 模式只支持 write-without-response；用 write-with-response 会超时。Boot 模式两种都行。

⇒ 连接超时 8 s，失败 3 次，每次重新扫描（设备可能在重启）。

3. 图 2 · 认设备（连上先做，升级前后各一次）

发 0x0A                     期 0x13  4B：构建号（YYYYMMDDnn，不是 vX.YY）
发 0x20 [01]                期 0x21  12B：id/stage/fw_hi/fw_lo/crc32/size      → S 蓝牙板
发 0x20 [02]                期 0x21  12B：同上                                  → M 主控
发 0x21 [01] / [02]         期 0x22  13B：型号串 "N2SE_S" / "N2SE_M"

判读：
  stage = 0 → 跑在 APP     stage = 1 → 跑在 BOOT
  fw_hi.fw_lo → 界面要显示的 v1.16
0x20[02] 一直无应答 ⇒ S 没跟 M 握上手（M 没上电 / 串口不通），提示"主控未就绪"，别说"设备异常"。

4. 图 3 · 测距数据（订阅后被动收，不用轮询）

0x07 距离      2B LE，单位分米 → /10 得米
0x0C 模式      1B：0=单点 1=两点（决定 0x07 的含义）
0x0A 推荐杆    2B LE：杆号（0xEF = 无推荐）
0x08 坡度 / 0x09 垂直高差 / 0x06 电量

5. 图 4 · 自定义杆包下发（最容易做错的一段）

        ┌─────────────────────────┐
        │ App：填 13 行，算本地 CRC │
        └────────────┬────────────┘
                     ▼
        ┌─────────────────────────┐
        │ 0x0D off=0x0000 n=28     │  发 28B
        │ 0x0D off=0x001C n=28     │  发 28B     每帧间隔 400~500 ms
        │ 0x0D off=0x0038 n=12     │  发 12B
        └────────────┬────────────┘
                     ▼
               ◇ 每帧都收到 0x15 ◇──否(0x92/0x93/0x94)──► 重发该帧（≤2 次）
                     │是 ack=0x01
                     ▼
        ┌─────────────────────────┐
        │ 0x0E [01] 提交            │
        └────────────┬────────────┘
                     ▼  200 ms 后开始轮询，间隔 200 ms
               ◇ 0x0F → 0x15 ack=0x02 ◇──否(0x81 处理中)──► 继续轮询（总 8 s）
                     │是                └──否(0xE1)──────► 重试一次，再失败报错
                     ▼
               ◇ 返回 crc == 本地 crc ◇──否──► 报错"主控校验不一致"
                     │是
                     ▼
        ┌──────────────────────────────────────┐
        │ 完成：主控自动切到第 5 档「自定义 Pro」 │
        └──────────────────────────────────────┘

读状态（进页面就该做一次）：

发 0x0E [04]  →  200 ms  →  0x0F  →  0x15 ack=0x04
显示：valid / ver / count / crc
   valid=0        → 主控无自定义表
   crc 相等        → 已是最新
   crc 不等        → 需要更新

擦除：0x0E[03] → 轮询 → 0x15 ack=0x03；擦完主控自动退回第 1 档。

0x15 六字节：ack, valid, ver, count, crc_lo, crc_hi

ack含义App 动作
0x01分片已收到继续下一片
0x81已受理，处理中继续轮询，不算结束
0x02提交完成比对 CRC
0x03擦除完成
0x04状态查询结果刷新界面
0x91主控链路未就绪提示稍后再试
0x92/93/94第 1/2/3 片被拒（串口没发出去）重发该片
0xE1主控 600 ms 无应答重试一次（S 内部已重试 1 次）
0xE2S 侧这一帧没发出去重试
0x82~0x8F主控 Modbus 异常（`0x80\code`）显示错误码

6. 图 5 · OTA 升级

        ┌──────────────────────────────┐
        │ 进 Boot：53 A2 04 00 FF 01 F9 01 │
        └──────────────┬───────────────┘
                       ▼  BLE 断开，等 1~2 s 重新扫描连接（名字不变）
        ┌──────────────────────────────┐
        │ 0x0101 握手（EB90）           │  期 0x0102（含 maxpkt）  ⇒ 3 s
        └──────────────┬───────────────┘
                       ▼
        ┌──────────────────────────────┐
        │ 0x0201 参数：size+SHA256+pkt  │  期 0x0202            ⇒ 3 s
        └──────────────┬───────────────┘
                       ▼
        ┌──────────────────────────────┐
        │ 0x0301 循环发数据（128B/包）   │  期 0x0302 ACK
        └──────────────┬───────────────┘     收到 0x0303 NACK → 从该 seq 重发
                       ▼
        ┌──────────────────────────────┐
        │ 0x0401 SHA 校验               │  期 0x0402（比对 32B）  ⇒ 失败=0x11
        └──────────────┬───────────────┘
                       ▼
        ┌──────────────────────────────┐
        │ 0x0501 完成                   │  期 0x0502 status=00
        └──────────────┬───────────────┘     ⇒ 每 500 ms 重发，最多 20 次
                       ▼
              设备重启 → 断开 → 重连 → 0x20 复查版本/CRC

Status：0x00 OK / 0x11 SHA 失败 / 0x21 序号错 / 0x22 长度错 / 0x23 Flash 错 / 0xFF 应用超时

实测：S 板 360 包 ≈ 4 s；M 主控 755 包 ≈ 12 s。

8. 状态机（App 侧）

   [空闲] ──连接──► [已连接] ──0x0A/0x20──► [已识别]
                        │                        │
                        │                   杆包页 ──► [下发中] ──完成──► [已识别]
                        │                   升级页 ──► [进Boot] ──重连──► [Boot模式]
                        │                                   └─升级完成──► [已识别]
                        └──断线/关机──► [空闲]（提示"设备已休眠，请按键唤醒"）
现象真实原因App 提示
扫不到设备被别人连着 / 5 min 无按键自动关蓝牙设备已被连接或已休眠
命令无应答没订阅通知 / 用了 write-with-response检查订阅与写方式
只收到部分应答只解析了 54A1，漏了 53A2两种帧头都解析
0x91主控链路未就绪（刚上电/升级中）稍后重试
0xE1主控 600 ms 未应答重试一次

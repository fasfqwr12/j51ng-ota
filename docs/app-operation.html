J51NG 操作流程（App 用户视角）

配套阅读：PROTOCOL_FLOW.md（帧怎么发）· APP_PROTOCOL_SPEC.md（字段细节）
本文只讲人在界面上怎么点、点了之后设备发生什么、出问题看到什么。

0. 设备本体先会用

操作结果
长按电源键开机亮屏；蓝牙同时开着；8 s 没按键 → 息屏待机（蓝牙还开着）
息屏待机时按任意键立即唤醒
5 min 没有按键自动关蓝牙（省电）
关蓝牙后 8 s自动关机
⚠️ 所以：先开 App 再开机，或者开机后 5 分钟内必须连上，否则蓝牙已经关了，得按键唤醒。

2. 连接页

界面元素点下去发生什么成功显示失败显示
连接扫描 AIMTECH* → 连接 → 订阅通知 → 读 MTU已连接 + 设备信息见下表
断开主动断链（必须断，否则设备不广播）未连接—
读状态0x0A + 0x20[1] + 0x20[2]S v1.16 / M v1.83 / APP 模式主控未就绪

失败提示对照

情况提示文案
扫不到未发现设备：请确认已开机、2 米内、未被其他手机连接
连上没反应设备未就绪：请稍后重试
主控无应答主控未就绪：请等设备启动完成
连接中途断开设备已休眠：请按键唤醒后重连

3. 测距页（日常用得最多）

开机 → 连接 → 对准目标 → 按键测距
   → App 实时显示：距离(m) · 推荐杆 · 坡度/高差 · 电量
  • 数据是设备主动推的，App 不用轮询
  • 推荐杆没有值时显示"—"（设备判定不适合推荐）

4. 杆包页（自定义 Pro）

4.1 第一次用

进页面 → 自动「读取主控状态」
   ├─ 主控：无自定义表（valid=0）→ 提示"还没有自定义杆包"
   ├─ 主控：有表且 crc 相同     → 显示"已是最新"
   └─ 主控：有表但 crc 不同     → 显示"需要更新"

4.2 改数值并下发

步骤操作界面反馈
1每行填「最近 ~ 最远」（单位：码）右侧自动算 均值 ± σ
2点「下发到主控」进度：第 1/2/3 片 → 提交 → 校验
3等结果（≤8 s）✅ "已写入，设备已切到第 5 档 Pro"
4—❌ "主控校验不一致，请重试"
下发成功 = 设备自动切到第 5 档，不用再去设备上手动切档。
设备设置页里第 5 档只有在表有效时才出现，表被擦除后会自动退回第 1 档。

4.3 其他按钮

按钮作用影响
载入默认只填本地默认表不动设备
擦除清掉主控里的表档位退回第 1 档

5. 升级页

① 扫描设备       → 显示 S / M 两块板的版本与 CRC
② 选固件         → 本地 .bin（显示版本/大小/CRC）
③ 开始升级       → 进度条 + 包计数（M≈755 包/12s，S≈360 包/4s）
④ 完成后         → 设备重启 → 自动重连 → 复查版本

顺序（点了"一键升级"就按这个走，不用管）：

主控 M  →  重启验证  →  蓝牙板 S  →  断连重连验证

注意

  • 升级中不要下发杆包（两者互斥，同时做会把表写坏——主控有 CRC 兜底会拒收，但仍要避免）
  • 升级蓝牙板时一定会断连，属正常
  • 升级期间保持亮屏、App 在前台、别切后台

6. 常见问题（用户口径）

用户说实际原因怎么答
"搜不到设备"设备已自动关蓝牙（5 min 无操作）按任意键唤醒再扫
"搜不到，但屏幕亮着"已连了另一台手机那台先断开
"连上了没数据"没订阅通知（App bug）报开发
"杆包发不进去"主控没上电/串口没通（0x91/0xE1）重启设备再试
"发了杆包但档位没变"提交没成功（CRC 不一致或超时）看提示，重发一次
"升级到一半断了"蓝牙板升级正常断连等 2 s 重连查版本

7. 一页纸速查

开机 → App 连接 → ①看版本对不对 ②测距能用 ③杆包能读 ④升级前先查版本
任何"没反应"：先看是不是 5 分钟没按 → 蓝牙自动关了
任何"扫不到"：先看是不是别人连着 → 设备连上就不广播
